## 适用范围

本手册写给负责「医美选择」专题站日常更新的人，按任务给出操作步骤，覆盖改稿、导读页、导航、图、封面、样式、站点信息、定期复核、检查、发布、回滚和常见故障。元数据字段、正文写法、证据等级、自检规则和版式参数写在《工程化说明》，文字要求写在《写作规范》，本手册用到时注明出处，不重复。

网站、单文件预览、docx 和部署包全部由脚本从源文件生成。site/、site-preview/、dist/ 和 build/ 下的文件不手改，下一次构建会整体覆盖。页面上的文字改 content/ 下的源文件，页面的样子改 tools/ 下的样式和模板。

仓库根目录的 CLAUDE.md 是给自动化写作工具的约定，它引用《写作规范》全文，规范改动后不用另改 CLAUDE.md。

## 环境准备

### 软件

| 软件 | 当前版本 | 用途 | 安装 |
|---|---|---|---|
| Node.js | 22.23.4 | 全部构建脚本 | 官方安装包或 nvm，装 22 版 |
| Python 3 | 3.13 | 导读页生成、断链检查、部署包里的 set-domain.py | 系统自带或官方安装包 |
| npm 依赖 | mermaid 11.4.1、docx 9.7.1、axe-core 4.10.2 | 流程图预渲染、出 docx、无障碍检查 | 在仓库根目录运行 npm install |
| Playwright 与 Chromium | Playwright 1.63.0 | 出图、分享卡片图、无障碍检查 | 见下文 |
| 中文字体 | Noto Sans CJK SC、Noto Serif CJK SC、AR PL UKai CN | 图和分享卡片图里的中文 | 见下文 |
| LibreOffice | 近期版本 | 可选，把 docx 转成 PDF 核对版面 | 官方安装包 |

Playwright 没有写进 package.json。它要配合本机已装的浏览器使用，各台机器的情况不同，写死版本容易和已装的浏览器对不上。脚本先在仓库的 node_modules 里找 Playwright，找不到再去系统的全局目录找。本机没有全局安装时，在仓库根目录依次运行下面两条命令。

| 命令 | 作用 |
|---|---|
| npm install --no-save playwright@1.63.0 | 装进仓库的 node_modules，不改 package.json |
| npx playwright install chromium | 下载配套的 Chromium |

图和分享卡片图里的中文，由 Chromium 用本机字体排好，再存成 SVG 和 PNG。缺字体时，文字会显示成方框或换成别的字体，字宽跟着变，流程图里的框会对不齐。Linux 上运行 sudo apt install fonts-noto-cjk fonts-arphic-ukai；macOS 和 Windows 上安装 Noto Sans CJK SC 与 Noto Serif CJK SC。缺楷体时，分享卡片图上的署名改用宋体。网站本身只用系统字体，读者那边不需要装字体。

### 首次检查

装好以后，在仓库根目录先运行 npm install，再运行 npm run build。输出的最后一行写着断链 0 个，环境就可以用了。

## 命令

| 命令 | 做什么 | 要先运行 |
|---|---|---|
| npm run lint | 按《写作规范》自检全部篇目与导读页，有 error 时退出码为 1 | 无 |
| node tools/lint.mjs 文件 | 只检查指定的文件 | 无 |
| node tools/renumber.mjs 文件 --write | 按首次出现的顺序重排引用编号和文献表 | 无 |
| python3 tools/gen_landing.py | 重新生成 22 个导读页 | 无 |
| npm run figures | 出图，写入 build/figures/ | 无 |
| npm run site | 生成 site/ 与 site-preview/index.html，生成前清空 site/ | figures |
| npm run og | 生成每页的分享卡片图，写入 site/og/ | site |
| npm run docx | 生成 dist/ 下的三份 docx | figures |
| npm run check | 检查 site/ 的内部链接和锚点 | site |
| npm run a11y | 无障碍抽查 12 页；npm run a11y -- --all 检查全部页面 | site |
| npm run build | 依次运行 lint、figures、site、og、docx、check | 无 |
| npm run package | 生成部署包 dist/医美选择网站-日期.zip | og |
| npm run preview | 在 http://127.0.0.1:8080 预览 site/ | site |

npm run site 会清空 site/，分享卡片图也在里面，所以单独运行 site 以后要再运行 og，npm run build 已经按这个顺序排好。npm run build 里的 lint 有 error 时构建照常往下走，要看输出里 lint 的合计一行。

## 日常更新流程

1. 拉取最新的分支，运行 git pull origin claude/clever-wright-axh5rf。
2. 改源文件，做法见常见任务一节。
3. 对改过的文件运行 node tools/lint.mjs，error 全部改掉，warn 逐条判断。
4. 运行 npm run build，最后一行的断链为 0。
5. 改过样式、模板或交互图时，运行 npm run a11y，问题为 0 类再往下走。
6. 运行 npm run preview，按人工检查一节看改过的页面。
7. 提交并推送。site/ 有改动时，推送会触发 GitHub Pages 发布。
8. 用自有服务器时，运行 npm run package，按发布一节上传。

## 常见任务

### 修改一篇文章

1. 打开 content/articles/篇号.md 修改。字段含义和正文写法见《工程化说明》的内容模型一节。
2. 改到获批产品、监管要求、价格规则这类会过期的事实时，先查原始来源，再把元数据 verified 改成核查当天的日期。网站篇首的署名行显示这个日期。
3. 增删引用以后运行 node tools/renumber.mjs content/articles/篇号.md --write。新增的文献按 GB/T 7714 写进文末的参考文献表，未核实完整的文献按《工程化说明》的引用规则处理。
4. 证据等级变动时，元数据 evidence 和文末 ::: evidence 段里的等级一起改，自检会比对这两处。
5. summary 保持在 200 至 300 字，takeaway 保持一句。
6. 这一篇的标题、结论句、面诊问题或今天能做的一件事有改动，而它又是生成导读页的来源时，运行 python3 tools/gen_landing.py，导读页里的摘引随之更新。
7. 按日常更新流程构建、检查、提交。

### 新增一篇文章

1. 新建 content/articles/45.md，篇号接在最后，元数据按《工程化说明》的字段表填齐，status 写修订。
2. category 只能填 tools/lib.mjs 里 CATEGORIES 列出的子分类。
3. 要让它进导读页，在 tools/gen_landing.py 对应条目的 ids 里加上篇号，ids 的顺序就是导读页上的阅读顺序，改完重新生成；手写的 aoxian、buanxin 两页直接改 md。tools/nav.mjs 的 ids 只在某个导读页还没上线时用来给出替代链接，加上篇号保持一致即可。元数据里的 problems 和 needs 只作记录，构建时不读取。
4. 有相关篇目时填 related，页面底部会列出。
5. 上一篇、下一篇按篇号排序自动生成。首页、篇目页、子分类页、搜索索引、站点地图、分享卡片图和 docx 里的篇数随之更新。
6. 按日常更新流程构建、检查、提交。

### 新增子分类

1. 在 tools/lib.mjs 的 CATEGORIES 里加上名称，列表顺序就是网站和 docx 里的顺序。
2. 在 tools/build-site.mjs 的 CAT_INTRO 里写一句介绍，首页卡片和子分类页会显示；不写时这两处只出名称。
3. 子分类页的网址按列表顺序编号，从 c/1.html 起。在中间插入会让后面的网址顺延，外部已经引用的网址会指向别的子分类，新的子分类加在列表最后。

### 修改导读页

手写的 aoxian 和 buanxin 直接改 content/landing/ 下的 md 文件。其余 22 页在 tools/gen_landing.py 的 PAGES 里改，改完运行 python3 tools/gen_landing.py。每一条里，situation 是典型情境，conclusion 是先说结论的几段，takeaway 是结论句，ids 是阅读顺序，today 指定今天能做的一件事取自哪一篇，emergency 为 True 时页面带急诊框。直接改这 22 个 md 文件，下次生成时会被覆盖。生成时，这 22 页的 verified 统一写成运行当天的日期。

新增一个导读页，在 PAGES 里加一条，或者参照 aoxian.md 的元数据手写一个 md 文件；再在 tools/nav.mjs 的 PROBLEMS 或 NEEDS 里加一条，slug 与文件名一致。按问题的导读页还可以放进首页的部位图，标签的文字和坐标写在 tools/build-site.mjs 的 navMapSvg 里，要手动摆放。

### 修改导航

| 要改的 | 位置 |
|---|---|
| 按问题、按处境两组的名称、顺序和对应导读页 | tools/nav.mjs 的 PROBLEMS、NEEDS |
| 首页从这里读起的三组篇目 | tools/nav.mjs 的 ENTRIES |
| 首页部位图的标签与连线 | tools/build-site.mjs 的 navMapSvg |
| 栏目导航的篇目、导读、搜索、文献、声明 | tools/build-site.mjs 的 siteHeader |
| 首页紧急情况框的三条与三个链接 | tools/build-site.mjs 的 homePage |

### 新增或修改一张图

1. 先按《写作规范》的配图一节判断要不要画。一张图只讲一件事，文字已经说清的不画。
2. 在 tools/figures.mjs 或 tools/figures2.mjs 里登记，写明 kind、alt 和 caption。alt 是替代文字，caption 是图注，写一句陈述，不下判断。
3. kind 有三种。mermaid 写 src，构建时预渲染成 SVG；svg 写 svg() 函数，输出静态 SVG；interactive 写 html()，输出带控件的网页版本，另写 staticHtml() 或 svg() 供出 PNG 用，没有静态帧的加 noPng: true。交互图的脚本写在 tools/figures-runtime.js，在 init() 的 reg 里按图名登记，网页元素带上 data-fig="图名"。
4. 颜色只用主题变量，前景 --ink，背景 --paper，次要文字 --ink3，灰阶 --fill-1 至 --fill-3，深浅两种配色都能读。不加红圈、箭头强调和重点标签。mermaid 的 src 里不写颜色，tools/render-figures.mjs 会把占位色统一换成主题变量。
5. 交互图要能只用键盘操作，状态变化写进 aria-live 区域；系统开启减少动态效果时，不播放连续动画。
6. 在正文需要的位置单独写一行 ::: figure 图名，下一行写 :::。自检会检查图名是否登记。
7. 运行 npm run figures，再运行 npm run build。build/figures/ 里的 PNG 是 2 倍分辨率，docx 和微信公众号都用这一份。

### 加封面图

1. 按《写作规范》的配图一节出图。封面为 2.35:1 横版，高明度、低饱和的中性色，画面内没有文字。
2. 文件放进 content/covers/。建议宽 1600 像素以上，JPEG 或 WebP 格式，单张 300 KB 以内。
3. 文章封面在该篇元数据里加一行 cover，值为文件名，例如 cover: 20.jpg。栏目首页的封面写在 tools/site.config.json 的 cover。
4. 封面图属于氛围图，网页上的替代文字留空，读屏软件会跳过它。单文件预览和 docx 不放封面。
5. 运行 npm run site 后预览。

### 修改界面样式

1. 颜色、字体和版宽改 tools/tokens.css，版面改 tools/site.css。site.css 里不写颜色值，只引用令牌。令牌的取值与用途见《工程化说明》的视觉与排版一节。
2. 改文字色或底色以后，正文类文字与底色的对比度保持在 4.5 比 1 以上，npm run a11y 会检查。
3. 下表这几处各有一份颜色，改令牌时一起看。

| 位置 | 内容 |
|---|---|
| tools/og-images.mjs | 分享卡片图的底色与文字色 |
| tools/render-figures.mjs 的 LIGHT_VARS | 图的 PNG 版本用的浅色值 |
| tools/build-docx.mjs | docx 的颜色，按正式文档版式固定，不跟网站变 |
| tools/build-site.mjs | 站点图标和 theme-color |

4. 版面在四个宽度上切换。1200 像素以上文章页分三栏；640 像素以下按手机排版；560 像素以下面部图改为上下排列；520 像素以下隐藏首页部位图。
5. 改完在 1440 和 390 两种宽度、深浅两种配色下，看首页、第 03 篇（表格与交互对照表）、第 20 篇（交互动画与引用预览），再看一次打印预览。

### 修改站点信息、版次与域名

下表的字段都在 tools/site.config.json 里，改完运行 npm run build。改 cname 后，规范网址、站点地图和分享图地址一起换成新域名。

| 字段 | 用途 |
|---|---|
| title | 栏目名，用于页头、网页标题和分享信息 |
| description | 首页的页面描述 |
| baseUrl | 没有自定义域名时的网址，现为 GitHub Pages 地址 |
| cname | 自定义域名，填了以后网址都按它生成，并输出 CNAME 文件 |
| author | 网页元数据和结构化数据里的作者 |
| parent | 上层站点的字标与链接，显示在页头左上角 |
| cover | 栏目首页封面图的文件名，空着不出封面 |
| edition | 版次，显示在网站页脚、首页和正文 docx 的卷首 |

### 定期复核

1. 会过期的事实每六个月复核一次，政策有变动时随时查。类别和首选来源见《工程化说明》的会过期的事实一节。
2. 列出各篇的核查日期并按日期排序，运行 grep -H "^verified:" content/articles/*.md | sort -t: -k3，排在前面的先查。
3. 复核后更新 verified；内容有改动的，按修改一篇文章的步骤处理。
4. 《工程化说明》待核清单里的条目，查到原始来源的，改正文并从清单里删去；仍查不到的保留。
5. 一轮复核做完，改 tools/site.config.json 的 edition，在《工程化说明》的修订记录里加一行。

## 检查

### 自动检查

| 命令 | 通过标准 |
|---|---|
| npm run lint | error 为 0，warn 逐条看过 |
| npm run check | 断链为 0 |
| npm run a11y | 问题为 0 类 |

自检脚本只能查出形式问题。有没有替读者标注感受，删掉一句以后信息少没少，仍要逐句读。

### 人工检查

1. 在 390 像素宽度下看改过的页面，没有横向滚动。
2. 切换到深色，文字、图和表格都能读。
3. 改过交互图时，用 Tab 键和回车走一遍，播放、拖动、切换都能用。
4. 点正文里的引用编号，宽屏在右栏出现文献，窄屏从底部弹出，按 Esc 能关闭。
5. 在搜索页搜一个这次改动里的词，能搜到改过的页面。
6. 用浏览器的打印预览看一篇文章，页头、目录和交互控件不出现。
7. docx 有改动时，转成 PDF 翻看改过的页，命令为 soffice --headless --convert-to pdf --outdir build dist/医美选择-正文.docx。

## 发布

### GitHub Pages

.github/workflows/pages.yml 在两种情况下运行，一是推送到 claude/clever-wright-axh5rf 分支且 site/ 或工作流文件本身有改动，二是在仓库的 Actions 页面选「发布网站」后点 Run workflow。工作流把 site/ 原样发布，不重新构建，所以线上的内容就是本地构建后提交的 site/。

首次上线前，在仓库的 Settings → Pages 把 Source 设为 GitHub Actions。没有设置时发布会失败，日志里有 Get Pages site failed。默认网址是 https://lavitee2026.github.io/claude-cloud/。

用自有域名时，在域名的 DNS 里加一条 CNAME 记录指向 lavitee2026.github.io，把域名填进 tools/site.config.json 的 cname，重新构建并推送。发布分支改名时，同时改 pages.yml 里的 branches。

### 自有服务器或对象存储

1. 运行 npm run package，得到 dist/医美选择网站-日期.zip。同一天重复打包会覆盖同名文件。
2. 解压后，把「医美选择网站」文件夹里的全部内容上传到网站目录，根目录或子目录都可以，例如 /yimei/。
3. 在网站目录里运行 set-domain.py，带上完整网址，例如 python3 set-domain.py https://www.sooogooo.plus/yimei/。这一步给每页补上规范网址和分享图地址，生成站点地图，并把 404 页的链接改成完整网址。可以重复运行，换域名或换目录时再运行一次。
4. Nginx 的 404 设置、对象存储的设置和 ICP 备案要求，见包里的部署说明.txt。
5. 更新时用新包整体覆盖旧文件，再运行一次 set-domain.py。新包里的页面不带域名，不运行这一步，规范网址和站点地图会缺失。

## 回滚

GitHub Pages 上出问题时，用 git revert 提交号 撤回出问题的提交并推送，工作流会重新发布撤回后的 site/。git log --oneline -- site 列出改过网站的提交。

自有服务器上，上传新包之前保留上一版的 zip，出问题时用上一版整体覆盖，再运行 set-domain.py。没有保留时，运行 git checkout 提交号 检出上一版，运行 npm run package 重新打包，再运行 git checkout claude/clever-wright-axh5rf 回到分支。dist/ 下的 docx 入库，要取回旧版时运行 git checkout 提交号 -- dist/医美选择-正文.docx。

## 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| npm run docx 报找不到 docx | 依赖没装 | 在仓库根目录运行 npm install |
| npm run figures 或 og 报找不到 playwright，或者找不到浏览器 | 本机没有 Playwright 或配套的 Chromium | 按环境准备一节安装 |
| 图或分享卡片图里的中文是方框，或者字体不对 | 缺中文字体 | 装好字体后重新运行 npm run figures 和 npm run og |
| 分享卡片图打不开，site/og/ 是空的 | npm run site 清空了 site/ | 运行 npm run og |
| 改了 mermaid 图，网站上没变 | 网站读取 build/figures/ 里预渲染的 SVG | 先运行 npm run figures，再运行 npm run site |
| 自检报引用编号顺序不对或编号缺失 | 增删引用后没有重排 | 运行 renumber.mjs 加 --write；文献表缺条目时手动补上 |
| 自检报图名未登记 | ::: figure 后的图名写错，或者没有登记 | 对照 figures.mjs 与 figures2.mjs 的登记名 |
| 改过的导读页，重新生成后改动没了 | 这一页由 gen_landing.py 生成 | 改 gen_landing.py 里的数据 |
| 发布失败，日志里有 Get Pages site failed | 仓库没有开启 Pages | 按发布一节设置 Source |
| 推送以后网站没更新 | 只推了源文件，没有重新构建并提交 site/ | 本地运行 npm run build，提交 site/ 后推送 |
| 双击本地的 html 文件打开，搜索不能用 | 浏览器不允许本地文件读取搜索索引 | 运行 npm run preview，用网址打开 |
| 无障碍检查报 color-contrast | 改过的颜色对比度不够 | 调整 tokens.css 的取值，到 4.5 比 1 以上 |
| 子目录部署后，404 页没有样式 | 没有运行 set-domain.py | 在网站目录运行 set-domain.py |

## 版次与记录

提交说明的第一行写这次改了什么，空一行后逐条列出主要改动。部署包 zip 已经写进 .gitignore，不进版本库。

版次写在 tools/site.config.json 的 edition，一轮修订或复核完成后更新。规格的改动，比如字段、写法、等级标准、版式参数，写进《工程化说明》，版本号加 0.1，并在修订记录里加一行；操作步骤的改动写进本手册，同样改版本号和日期。
