## 适用范围

本说明面向维护「医美选择」栏目的编辑和工程人员，规定内容怎样写成源文件、证据怎样核查和标注、自检脚本检查什么、网站和 docx 怎样从同一份源文件生成，以及修订一篇稿件的完整流程。读者文档的文字规范以仓库根目录的《写作规范》为准，本说明不重复。

试点阶段覆盖第 01、12、20、24、41 篇和两个落地页。其余 39 篇以原稿形式收进网站，标注为原稿，等试点方向确认后按同一流程修订。

## 内容模型

每篇稿件是一个 Markdown 文件，开头是元数据块，正文由小标题、段落、列表、表格和四种容器块组成。解析器在 tools/lib.mjs，网站、docx 和自检脚本共用同一个解析结果，三个产物不会各说各话。

### 元数据字段

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| id | 是 | 01 至 44 | 篇号，两位，决定网址与排序 |
| title | 是 | 文本 | 主标题，系列稿四五字 |
| subtitle | 是 | 文本 | 副标题，一句 |
| category | 是 | 六个子分类之一 | 决策框架、光电类项目、注射类项目、外科类项目、机构与医生甄别、术后护理与风险 |
| page_type | 是 | 支柱页、总览、项目、风险、方法、识别、话术等 | 内部页型，不在读者页面出现 |
| evidence | 是 | A、B、C、A/B、B/C | 证据等级，只在文末显示 |
| batch | 是 | 1、2、3 | 原发布批次 |
| status | 是 | 修订、原稿 | 网站据此提示 |
| verified | 是 | 日期 | 最近一次核查时效事实的日期 |
| emergency | 是 | true、false | 为 true 时必须有急诊框 |
| problems | 否 | 问题导航的名称列表 | 决定出现在哪些问题落地页 |
| needs | 否 | 需求导航的名称列表 | 决定出现在哪些需求落地页 |
| related | 否 | 篇号列表 | 页面底部的相关篇目 |
| summary | 是 | 200 至 300 字 | 速读摘要 |
| takeaway | 是 | 一句 | 先说结论，排版为左竖条 |

### 正文块

| 写法 | 含义 | 网站 | docx |
|---|---|---|---|
| ## 小标题 | 一级小标题，正文只允许这一级 | h2，下方细线 | 一级标题，下方细线 |
| 空行分隔的文字 | 自然段 | p | 首行缩进 480 twips |
| 1. 起头的行 | 有序列表，限读者对照着用的小节 | ol | 编号条目，左缩进与悬挂各 480 |
| 竖线表格 | 表格 | 水平细线表 | 黑色水平细线表，无竖线 |
| ::: emergency | 急诊框，短横线起头的每行一条，最后一行为处理说明 | 黑框 | 带边框的段落组 |
| ::: figure 名称 | 插图，名称须在 tools/figures.mjs 登记 | 内嵌 SVG 或交互图 | PNG 位图 |
| ::: evidence | 文末证据等级与来源说明 | 楷体小字 | 楷体小字注 |
| [1] [1,2] [1-3] | 文献引用，顺序编码 | 上标链接 | 上标 |
| ## 参考文献 下的 [n] 行 | 文献表，GB/T 7714 | 有序文献表 | 小字文献表 |

署名「于意云 何」、免责声明和利益声明由构建脚本统一加，不写进源文件。网站每篇末尾都有；docx 在卷首集中一次，每篇末尾只留署名。

### 项目页的七节

光电、注射、外科三类的项目页，正文按原理、能解决的问题、效果边界、风险与恢复期、不适合做的情形、费用组成、面诊时可以问的问题七节写成。效果边界和风险与恢复期两节按综述的写法写：给出数字区间，写明数据来自什么研究、多少人，几项研究的结论一致还是不一致；单项研究的局限写进文末的证据说明，正文只留一句。

## 证据体系

### 来源层级

核查一条事实时，按下表从上往下找来源，找到能直接支撑的最高一层就停。新闻报道只用来定位原始来源；原始来源找不到时，引用新闻报道并在待核清单里登记。

| 层级 | 来源类型 | 例子 |
|---|---|---|
| 一 | 法律法规、部门规章、规范性文件、官方公告 | 医疗美容服务管理办法、国家药监局公告 |
| 二 | 产品注册证与说明书、药监数据库 | 注册证上的适用部位、说明书警示 |
| 三 | 系统综述、Meta 分析、随机对照试验 | 肉毒毒素维持时间的 Meta 分析 |
| 四 | 国内外专家共识、临床指南 | 中国黄褐斑诊疗专家共识 |
| 五 | 队列研究、病例系列、叙述性综述 | 填充剂栓塞率的多中心回顾研究 |
| 六 | 上市公司公告、企业新闻稿 | 新产品获批公告 |
| 七 | 主流媒体报道 | 新闻发布会报道 |

### 等级标准

下面的定义按现有 44 篇的用法归纳，试点期间请作者确认。

| 等级 | 判定 |
|---|---|
| A | 主要结论由第一至三层来源直接支撑 |
| B | 主要结论由第四、五层来源支撑，或由多份第一至三层来源归纳得出 |
| C | 主要结论来自临床常规与行业经验的归纳，缺少可引用的研究 |
| A/B、B/C | 一篇里的结论分属两级，前一级为主要结论所在的级别 |

等级只出现在文末的证据说明里，和来源说明写在同一段。读者页面不放方法论章节和可信度分层。

### 引用规则

正文用方括号顺序编码，按首次出现的先后从 1 编起，同一文献沿用同一编号。文献表按 GB/T 7714 著录，期刊文章补 DOI。未核实完整的文献，给出内容描述加可定位信息，比如发布机构、日期、公告编号或网址，不补全题名，不编造卷期页码。外文机构名和数据来源的国别写在文末证据说明里，正文用中文描述研究本身。

编号写乱时，运行 node tools/renumber.mjs 文件 --write，脚本按首次出现的顺序重排正文编号和文献表，相邻的 [1][2] 合并为 [1,2]，三个以上连续编号合并为区间。

## 写作规范自检

tools/lint.mjs 把《写作规范》里能机器判断的条目写成规则。error 必须改；warn 交给作者判断，比如话术原文里的永久，药品说明书里的成分，属于合理用法。

| 规则 | 级别 | 检查内容 |
|---|---|---|
| bold | error | 加粗 |
| dash | error | 破折号 |
| label-colon | error | 行首的标签词冒号 |
| colon | warn | 冒号，引出话术引文的除外 |
| dquote | warn | 双引号，改用直角引号 |
| banned | error | 禁用词，拆开、拆解、拆穿、一刀、砍、落盘、立住 |
| bigword | warn | 刻意大词，结构、机制、维度、路径等十二个 |
| verb | error | 万能动词与视角腔，解读、解构、叙事、从某某视角 |
| contrast | warn | 对照句式 |
| naming | error | 迂回命名 |
| announce | warn | 报幕句 |
| emotion | error | 伪情绪拍 |
| absolute | warn | 绝对化表述 |
| superlative | warn | 替读者排序的最高级 |
| position | warn | 位置化与端点化表述 |
| meta | warn | 展示推理过程 |
| halfwidth | error | 中文语境里的半角标点 |
| spacing | warn | 中文与数字、英文之间没有留白 |
| heading-depth | error | 正文出现两级以上的小标题 |
| heading-question | warn | 小标题带疑问 |
| one-liner | warn | 单句成段 |
| list-place | warn | 列表出现在对照用小节以外 |
| pairing | error | 引号、括号、书名号不配对 |
| cite-order 等 | error | 引用不按首次出现编号、编号缺失、文献未被引用 |
| meta、emergency、evidence | error | 元数据缺项、急诊框缺失、文末等级与元数据不一致 |
| summary-length | warn | 速读摘要不在 200 至 300 字附近 |

运行 npm run lint 检查全部修订稿，或者 node tools/lint.mjs 文件 检查单篇。有 error 时退出码为 1，可以接进提交前的检查。脚本只能查出形式问题，有没有替读者标注感受、删掉一句信息少没少，仍要逐句读。

## 网站

### 两个构建目标

网站由 tools/build-site.mjs 生成，同一套页面模板输出两份。site/ 是多页静态站，每篇一个网址，样式和脚本是独立文件，适合部署到自有域名；site-preview/index.html 把所有页面放进一个文件，用网址里的井号切换页面，用于 claude.ai 私有页面预览，不依赖任何外部资源。

| 页面 | 多页站网址 | 单文件网址 |
|---|---|---|
| 首页 | index.html | #home |
| 篇目 | a/20.html | #a-20 |
| 落地页 | g/aoxian.html | #g-aoxian |
| 文献总表 | refs.html | #refs |
| 声明 | about.html | #about |

### 视觉与排版

文字一律深灰 262626，结构线用深绿 1F4A38，和 docx 的版式一致；报头上下两条粗线，结论句左侧竖线，一级小标题下方细线。正文用系统宋体，标题与标签用系统黑体，证据说明用楷体。网站不加载网络字体，原因是谷歌字体在国内访问不稳定，系统字体在各平台都有对应的中文字体。

深色模式下各颜色有对应的值，结构线换成浅一些的绿，保证对比度。全站只有图表区域使用灰阶填充，没有其他装饰色。

### 交互与动效

动画只用在过程本身随时间变化的地方，目前是第 20 篇的肉毒毒素作用与消退。动画由读者点击播放，可以暂停、拖动时间轴；系统开启减少动态效果时，播放改为五个时间点逐帧切换。不做入场动画、视差滚动和背景视频。

### 搜索

首页的搜索框在本地过滤篇目，匹配标题、副标题、摘要和子分类，不依赖服务器。

### 部署

多页站可以直接放到任何静态托管上。用 GitHub Pages 时，把 site/ 目录发布为站点根目录；用自有域名时，在 DNS 加一条指向托管服务的记录。微信公众号不支持 SVG，发到公众号的图用 build/figures/ 里的 PNG。

面部图是示意线稿，部位的范围不代表解剖边界，上线前需要医生审阅。新增一张图时，在 tools/figures.mjs 登记名称、类型、图注和替代文字，正文用 ::: figure 名称 引用，自检脚本会检查名称是否登记。

## docx 版式

docx 由 tools/build-docx.mjs 用 docx 库生成，版式参数如下。

| 项目 | 参数 |
|---|---|
| 纸张与页边距 | A4，上 1420、右 1300、下 1420、左 1300 twips |
| 文字颜色 | 262626，不用彩色文字 |
| 结构线 | 1F4A38，报头上下粗线 sz12，结论句左竖条 sz12，一级标题下细线 sz4 |
| 表格 | 黑色 000000 水平细线，无竖线，无底纹，表头行加粗居中 |
| 字体 | 标题与加粗标签 Arial 与黑体；正文 Times New Roman 与宋体；小字注楷体 |
| 字号 | 主标题 22pt、副标题 13pt、一级标题 13pt、二级标题 11pt、正文 10.5pt、小字注 9.5pt、表格正文 9.5pt、表头 9pt、页脚 8pt 色 8A908A |
| 段落 | 正文首行缩进 480 twips；编号条目左缩进 480、悬挂 480 |

正文 docx 的结构为卷首（书名、版本、使用说明、急诊信息、统一声明）、导读（落地页）、篇目正文、文献总表。每篇另起一页，篇号与子分类一行，主标题、副标题、速读摘要、结论句、急诊框、正文、证据说明、参考文献、署名依次排列。

## 修订一篇的流程

1. 从 content/originals/ 把原稿移到 content/articles/，把 status 改为修订。
2. 列出全文的事实性陈述，按来源层级逐条核查，过期的改写，找不到来源的改为不确定的措辞或删除，登记待核项。
3. 按《写作规范》改文字，效果边界和风险两节按综述写法补数据。
4. 运行 node tools/renumber.mjs 文件 --write 整理编号，运行 npm run lint 直到没有 error，逐条看 warn。
5. 更新 verified 日期、problems、needs 和 related，检查相关落地页是否需要改。
6. 运行 npm run build，看网站与 docx 的渲染结果，提交。
